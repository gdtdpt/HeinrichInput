# 亨利五笔 1.1.4

> 发布日期：待发布　|　安装包：`HeinrichSetup-1.1.4.exe`　|　类型：PATCH（修候选窗位置，续 1.1.3）

## 修复

### 候选框仍会偏：改判「一次测量里哪个值更可信」

1.1.3 给候选框位置加了闸门（量到的位置必须跟上次可信位置对得上），当天就复现了三种偏，
而且都发生在**同一个按键的两次测量之间**：

| 现场 | 写组合串之前量到 | 写完之后量到（被采纳） | 真实位置 | 谁放行的 |
|---|---|---|---|---|
| 16:00:51 | 898（对） | 1214（剪切之前的旧值） | 914 | Ctrl+A 留下的「放行」 |
| 16:05:10 | 898（对） | 1780（旧值） | 912 | 鼠标停在旧位置上 |
| 15:45:35 | 898（对） | 1504（旧值） | ~910 | 纵向差 58px 被当成「换行」 |

三次都是**同一瞬间的两次测量，一个对一个错，而闸门选了错的那个**。原因是它的判定顺序
把「按过某个键」「鼠标在旁边」「像换行」这些**推测**排在「写前 vs 写后」这个**直接对照**前面。

现在的做法：

- **首键仲裁提到最前面**：写组合串之前量一次、写完再量一次，两次差到两行高以上就信写之前
  那个——那时宿主排版还是干净的。唯一例外是写前那个值落在编辑区之外（那才是真的换了输入框，
  写前是上一个框的残留），此时不仲裁。
- **换行不再免检横向**：换行本身合理，但只允许往左（回到行首）或往右一个小字宽。真正的换行
  不会让插入符在同一瞬间往右跳 600px。
- **「放行」分两类，时效不同**：方向键 / Home / End / Ctrl+Z 是真的把光标挪了，放行条一直留到
  被用掉（紧接着打的那个字本来就该在新位置）；而 Ctrl+A、Esc 只是**推测**下一个键会让光标跳，
  中间插进来另一个 Ctrl 组合（Ctrl+X 之类）就作废——1.1.3 那次事故正是 Ctrl+A 置位后没人清。
- **同行往左跳一律放行**：删掉一段、全选替换、点回行首都是「从行尾跑回行首」，几百像素，而且
  极其常见。实测三次偏**全部是往右**（宿主回放的是更早、更靠右的位置），所以往左放行、
  往右仍然拦。

## 升级说明

- 直接运行 `HeinrichSetup-1.1.4.exe` 覆盖安装即可，用户数据（学习库、自定义词组、emoji 绑定）全部保留。
- 不需要关闭正在运行的程序，也不需要重启电脑；已开着的程序仍在跑旧 DLL，重启它们即切换到新版。
- 可在「设置」窗口标题栏确认版本号（应显示 `亨利五笔 · 设置 · v1.1.4`）。

## 完整变更

| 类型 | 内容 |
|---|---|
| 修复 | 首键仲裁（写前 vs 写后）提到闸门判定的最前面，不再被「放行」抢先 |
| 修复 | 仲裁的唯一例外：写前值落在编辑区之外时不仲裁（那才是真的换框） |
| 修复 | 「换行」不再免检横向：只允许往左或往右一个小字宽 |
| 修复 | 放行分 `Happened` / `Predicted` 两类；后者遇到另一个 Ctrl 组合作废 |
| 修复 | 同行往左跳（删段、全选替换、回行首）放行，避免删完一段后窗口冻在行尾 |
| 内部 | `keys::caret_move` 返回 `CaretMove`，替代 `is_caret_move` 的布尔值 |
| 内部 | `Gate::note_other_key(ctrl_chord)`：只由 Ctrl 组合键作废预测性放行 |
| 测试 | 闸门单测 12 → 17 条（含 16:00:51 事故的回放用例）；`clippy -D warnings` 干净、`cargo test --all` 全绿 |
