## 修复

### 候选框不再飞到「十几分钟前的地方」（D105）

1.1.2 让候选框「多量一次再摆」，当天就遇到了量不到救的情况：候选框跳到了**同一行但横向 700 多像素**
之外的地方，而那正是十几分钟前你在同一个输入框里打字时的位置。

原因是宿主程序（WorkBuddy、微信、浏览器等）内部缓存的光标位置**没跟着刷新**。我们把三条途径
（选区、组合串、窗口插入符）全问了一遍，得到的都是同一个旧值——因为它们读的是同一份缓存。
所以「多量几次」这条路走不通，得换一个判据：**这次量到的位置，和上一次确定正确的位置对得上吗？**

现在的做法：

- **记住上一次确定正确的位置**，每次量到新位置都要先跟它「对得上」才算数——同一个输入框内，
  一次跳出去几百像素是不可能的（打一个字光标才挪二三十像素）。
- **第一次按键时多问一次**：在把编码写进输入框**之前**先量一次（那时宿主排版还是干净的），
  写完再量一次；两次差得远，就信写之前那个。这一条正是挡住本次事故的关键。
- **对不上时窗口不跟着跳**，留在上一次的位置上；随着你继续上屏，它会按字数**慢慢往前挪**，
  不会僵在原地。等宿主把真实位置报上来，它立刻归位。
- **你主动移动光标时一律放行**：方向键、Home / End / PgUp / PgDn、Ctrl+A、Ctrl+Z，以及
  用鼠标点到输入框里的别处（指针就在量到的位置附近）。这些情况下窗口会立刻跟过去。
- **万一某程序用我们看不见的方式挪了光标**（脚本跳转、特殊编辑器的按键移动），连续三次
  报告同一个位置就会被认可，最多落后三个键。

取舍说明：宿主一直报错位置时，窗口会**落后几个像素**而不是停在精确位置。这是有意选的
——「落后」比「飞走」轻得多，而且看得懂。

## 升级说明

- 直接运行 `HeinrichSetup-1.1.3.exe` 覆盖安装即可，用户数据（学习库、自定义词组、emoji 绑定）全部保留。
- 不需要关闭正在运行的程序，也不需要重启电脑；已开着的程序仍在跑旧 DLL，重启它们即切换到新版。
- 可在「设置」窗口标题栏确认版本号（应显示 `亨利五笔 · 设置 · v1.1.3`）。

## 完整变更

| 类型 | 内容 |
|---|---|
| 修复 | 候选框位置：新增位置闸门（`gate.rs`），量到的坐标必须从上次可信位置「走得到」才采纳 |
| 修复 | 首键仲裁：写组合串前后的两次测量差 > 2em 时采用写前那个（排版干净时的值） |
| 修复 | 拒绝期间按上屏字宽慢跟随，窗口不再僵在原地，也不再跟着错值飞走 |
| 修复 | 复量（1.1.2 的机制）也要过闸门，不再把已拒绝的错值原样捡回来 |
| 新增 | 四个「光标被挪走」的重置信号：移动键、换行、换编辑区、鼠标指针邻近 |
| 内部 | `caret.rs` 的探测结果改为 `Measured{rect, source, view}`，视图矩形供闸门判「换了输入框」 |
| 测试 | 新增 12 条闸门单测（含 D105 现场的回放用例）；`clippy -D warnings` 干净、`cargo test --all` 全绿 |
